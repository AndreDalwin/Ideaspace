## Task 2: Add Settings > Images tab and image-model selection UI

### What Was Done

Created a new Settings tab named "Images" for selecting an image generation model from connected Google providers. The tab is positioned next to "Models" in the Server settings section.

### Key Findings

1. **Settings Pattern**: Settings pages follow a consistent layout with:
   - Sticky header with title, description, and search field
   - Grouped lists by provider using `useFilteredList` hook
   - RadioGroup for single-selection items (unlike Models which uses Switch for visibility)

2. **Provider Model Type**: The Provider model type from SDK has `modalities?.output` array (not `capabilities.output.image`). This is defined at line 1181-1183 in `packages/sdk/js/src/v2/gen/types.gen.ts`.

3. **Supported Providers v1**: Only `google` and `google-vertex` providers are supported for image generation in v1.

4. **Filtering Logic**: Two-tier filtering:
   - Primary: Check `modalities?.output?.includes("image")` for explicit image capability
   - Fallback: Check if model ID contains "image" substring (case-insensitive)

5. **Persistence Pattern**: Uses `globalSync.set("config", "image_model", value)` for optimistic update, then `globalSync.updateConfig({ image_model: value })` for server persistence with rollback on error.

6. **Icon Availability**: The "image" icon doesn't exist in the UI icon set. Used "photo" icon instead.

## Task 4: Google/Gemini Image-Generation Helper

### What Was Done

Implemented `ImageGen.generate()` helper under `packages/ideaspace/src/provider/image-gen.ts` that supports Google (Gemini) and Google Vertex (Imagen) image generation APIs.

### Key Implementation Patterns

1. **Config Integration**: Reads `Config.get().image_model` to determine provider/model in `provider/model` format
2. **Provider Support**: Only supports `google` and `google-vertex` - fails fast with `UnsupportedProviderError` for others
3. **Auth Patterns**:
   - Google: Uses `GOOGLE_GENERATIVE_AI_API_KEY` or `GEMINI_API_KEY` env vars, with config override support

4. **Response Normalization**: Returns consistent `Result` shape with `mime`, `bytesBase64`, optional `revisedPrompt`, and error fields
5. **Error Handling**: Custom error types for safety blocks (`SafetyBlockedError`), generation failures (`GenerationError`), and configuration issues (`MissingModelError`, `UnsupportedProviderError`)

## Task 5: Add image_generate Tool and Register in ToolRegistry

### What Was Done

Implemented the `image_generate` tool following the same pattern as other built-in tools (QuestionTool, BashTool, etc.) and registered it in the ToolRegistry.

### Key Implementation Patterns

1. **Tool Definition Pattern**: Used `Tool.define("image_generate", {...})` with:
   - `description`: Multi-line string explaining tool purpose and parameters
   - `parameters`: Zod schema with `prompt` (required) and `aspect_ratio` (optional enum)
   - `execute`: Async function returning `{ title, output, attachments, metadata }`

2. **Provider/Model Validation**: 
   - Parse `config.image_model` as `provider/model` format
   - Validate provider is `google` or `google-vertex`
   - Fail with clear actionable error pointing to Settings > Images

3. **Image Generation Flow**:
   - Call `ImageGen.generate(prompt)` to get `{ mime, bytesBase64, revisedPrompt }`
   - Convert base64 to Uint8Array with `Buffer.from(bytesBase64, "base64")`
   - Persist with `ImageStorage.persist(bytes, sessionID, messageID, mime)`
   - Return `FilePart` attachment with data URL and resource URI

4. **Attachment Structure**:
   ```typescript
   {
     type: "file",
     mime: "image/png",
     filename: "image.png",
     url: "data:image/png;base64,...",
     source: { type: "resource", clientName: "ideaspace", uri: "ideaspace://image/..." }
   }
   ```

5. **Metadata Returned**:
   - `provider`, `model`, `prompt` (always included)
   - `aspectRatio` (only when provided)
   - `mime`, `revisedPrompt`, `path` (from generation result)

## Task 5 Fix: Aspect Ratio Forwarding

### What Was Fixed

The original implementation had `aspect_ratio` as a tool parameter but didn't actually forward it to the image generation APIs.

### Changes Made

1. **ImageGen.generate() signature** (image-gen.ts:313):
   - Changed from `generate(prompt: string)` 
   - To `generate(prompt: string, opts?: { aspectRatio?: string })`

2. **callGoogleAPI() forwarding** (image-gen.ts:91-117):
   - Added `aspectRatio?: string` parameter
   - Conditionally adds `generationConfig.aspectRatio` to request body when provided
   - Only forwards when truthy (not undefined, null, or empty string)

3. **callVertexAPI() signature** (image-gen.ts:200-205):
   - Added `aspectRatio?: string` as 4th parameter (after getToken)
   - Prepared for future Vertex/Imagen aspect ratio support

4. **image_generate tool** (image_generate.ts:54-56):
   - Changed from `ImageGen.generate(params.prompt)`
   - To `ImageGen.generate(params.prompt, { aspectRatio: params.aspect_ratio })`

5. **Metadata key fix** (image_generate.ts:96):
   - Changed from `aspectRatio: params.aspect_ratio` (camelCase)
   - To `aspect_ratio: params.aspect_ratio` (snake_case per task requirements)

### Test Improvements

Updated tests to verify **actual forwarding behavior** (not just output strings):

1. **Capture request body**: Mock fetch now captures and stores the request body
2. **Verify forwarding**: Test checks `capturedRequestBody.generationConfig.aspectRatio === "16:9"`
3. **Verify omission**: Test checks `capturedRequestBody.generationConfig.aspectRatio === undefined` when not provided

## Task 5 Final Fix: Vertex Aspect Ratio Forwarding

### What Was Fixed

The `callVertexAPI` function was accepting the `aspectRatio` parameter but not forwarding it to the Vertex API request body.

### Changes Made

1. **Vertex request body building** (image-gen.ts:226-236):
   - Changed from inline `parameters: { sampleCount: 1 }`
   - To building a parameters object conditionally:
   ```typescript
   const parameters: { sampleCount: number; aspectRatio?: string } = {
     sampleCount: 1,
   }
   if (aspectRatio) {
     parameters.aspectRatio = aspectRatio
   }
   ```

2. **Provider tests** (test/provider/image-gen.test.ts):
   - Added `mockFetchWithCapture` function to capture request bodies
   - Added `capturedRequestBody` variable to store parsed request bodies
